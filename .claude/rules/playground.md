# Playground mode (`playground`, beta)

- Uses Code Lab 7.0's cap and repeat check, but its **own writer note and gate** (Oct 30): `PLANNER_NOTE_PG` (any interactive part, with `kind` quantity/process/compare/**structure**; `mark_hint` leads the hint with the kind) and `PG_GATE_QUESTIONS` (adds a "structure" question; `gate_one(playground=True)`). Code Lab 7.0 keeps `PLANNER_NOTE_4` / `GATE_QUESTIONS`. Before this, structure sections (layers, attention links, pipelines) were never marked and no playground drew a diagram.
- `PLAYGROUND_SYSTEM` "Your views": plotted charts, diagrams and AI views are equally available and mixable; a section about connected parts must show the structure itself. Bars get labels only for named categories; the runtime also thins crowded bar labels. Each marked section gets a playground from the ai-playground experiment (`Bloging-substack/ECommerce`): Haiku writes **one JSON spec** (slider/select/toggle/button/play/chart/readout plus short JS snippets). No separate plan call; the spec's `plan` field is the plan.
- `scripts/check-playground.mjs` dry-runs the spec with the experiment's validator (every snippet runs, no NaN, every control reaches a chart or readout, no chart that stays empty in every state reached, 60 Play ticks). Fails closed.
- **Layout check (soft, free):** on a pass the validator also returns `layout` (`layoutProblems`): shapes overlapping, sticking out of the plot, arrows with no room, labels cut inside shapes, link labels on shapes, a line mostly outside or capped at the top of a fixed y range, data never filling 40% of a fixed x range in any state, a link running through a third shape, a text mark past the plot, a heatmap bigger than a fixed x/y range. Measured with the renderer's own geometry (`structures.cjs` `chartFrame`, `shapeGeom`, `linkGeom`, `labelRoom`, `placeText`; `components.cjs` draws with the same functions). Not checked: graph/tree/sequence/matrix layouts (library-placed).
  - **Every state (Oct 31):** measured on up to 48 states the dry run reaches (`stateMarks`, thinned evenly), not only the first. A problem first seen later is reported once, ending with " (after the controls move, not at the start)". "Line outside the y range" is checked on the first state only (a slider at its extreme pushing a fitted line off the chart is normal).
  - **Fix order in `_pg_fix_layout`:** (1) code: `_pg_layout_autofix` (empty x or y range narrowed but not below an old start ≥ 0, 5% headroom for a line along a top of 1 or 100, y widened for a line outside it only up to `PG_WIDEN_MAX` = 3×, chart range fitted to a heatmap); kept only if it passes every check with fewer layout problems. (2) Haiku: `LAYOUT_REPAIRS` = 1 try (led by `LAYOUT_LEAD`) on what's left, same keep rule. Stats: `layout_seen`, `layout_code_fixed`, `layout_fixed`.
  - **Text marks** are placed by the renderer (`structures.placeLabels`): kept inside the plot (`placeText`: shifted/re-anchored at the left/right edge, moved down/up at the top/bottom), then nudged up or down (up to 48 px) off lines, areas, horizontal rules, arrows and earlier labels (not vlines: no up/down nudge clears them; at most 12 labels). Only a label wider than the plot, or one drawn across a line with no free spot in the **starting** view, is reported.
  - **Empty y range** (like x): the data (series, bars/areas from 0, points, hlines, rects, arrows) never fills 40% of a fixed y in any state → code narrows y (not below an old start ≥ 0). Oct 31, 175 playgrounds: 27 charts.
  - Oct 31, 167 saved playgrounds: 48 with a problem (all states) → 26 after `placeText` → 6 after the code fixes (4 diagrams, 1 clamped line, 1 range too far off). A diagram tidy pass with Jev picking between candidates is deferred until diagram numbers call for it (`playground-layout-plan.md`).
- **Our `shared/playground/` differs from the experiment:** `placeText`, `placeLabels`, `textBox` (+ `TEXT_CHAR_W`) in `structures.cjs`, their use in `components.cjs` and the validator's text check, and the all-states layout check + empty-y-range check in `validator.cjs`. Keep them when re-copying from `Bloging-substack/ECommerce`.
- **Nov 1 fixes from the rubric eval** (`playground-rubric-eval-results.md`; each measured on 206 saved playgrounds, all generic, no topic rules). Also ours, keep when re-copying:
  - `validator.cjs` **growing charts** (`noteGrowth`, `growing`): a chart whose data runs further along x with each button press / Play tick is never reported as an empty x range. The dry run presses twice, so `_pg_layout_autofix` used to narrow a "loss per step" chart to its first 3-4 points (eval rows 5, 8). Empty-x messages on the 206: 6 → 3, the 3 removed were all growing charts.
  - `validator.cjs` **legend message**: 2-6 lines/areas in 2+ colours and no text mark → a soft layout message (Haiku's 1 layout try adds words). 15 of 206 playgrounds; 14 get a layout call they didn't get before.
  - `structures.chartFrame`: bars on a fixed y get 4% room above `y[1]` (no message, no Haiku). The checker's range rules still use `spec.y`.
  - `components.cjs`: `fmt` writes 1e4-1e15 in full with commas (`262,144`, was `2.62e+5`); axis ticks use `fmtTick` (`200k`, `1.5M`), since the left margin fits ~6 characters. Tiny values (< 0.001) stay in e-notation.
  - `components.cjs`: point/points are drawn in their own clip grown by their radius (`-dot` clipPath, drawn after the other plotted marks), so a dot on the plot edge is whole.
  - `structures.fitText` / `fitNum`: tree boxes, graph node names, matrix name/row/column labels and sequence labels/tokens are squeezed up to 25% (SVG `textLength`) before being cut with …; numbers in matrix cells and under sequence tokens drop decimals and the leading zero (`-0.53` → `-.5`), never show a non-zero as 0 and never round a value below 1 to a whole number. Shape labels are unchanged (the checker reports those via `labelRoom`).
- **Nov 2 fixes from the rubric eval** (items #2 and #3 of the deterministic list; replayed on 182 playgrounds = 152 saved + 30 eval). Also ours, keep when re-copying:
  - `structures.manualGraph`: hand-placed graph nodes (`layout: 'manual'`) shrink (down to `GRAPH_MIN_R` = 6) until no two circles touch and no name drawn under a node (labels > 3 chars) lands on the node or value below it. Eval row 18 (beam-search tree, rows 36 px apart) drew 36 px circles on top of each other. `graph()` uses it; so does the validator.
  - `validator.cjs` layout messages for manual graphs: nodes / name-on-node / names side by side that still collide at the smallest size (with the units that would fit), and a text mark drawn on a node or its name. No code autofix; Haiku's 1 layout try gets the message. Fired only on eval row 18 of the 182 (manual graphs are rare).
  - `components.cjs` `offEdge`: a line or points past the y range get an arrow in their colour where they leave (one per stretch, ≥14 px apart, at most 8 per edge; a line and its own dots share them within 24 px) and, once per edge, the furthest value, like bars past the range. Straight 2-point lines (tangents, fitted lines) are skipped. Eval rows 1 (gradient descent at lr > 1) and 4 (degree 9+) had the curve silently cut. Shows in the first view of 5 of 152 saved playgrounds.
- **Nov 2 fixes, part 2** (items #7 and #4; replayed on the same 182):
  - `components.cjs` **bar values**: a chart with ≤12 bars and no text marks writes each bar's value just past its end (inside when there's no room), all values of a series in one style (`barValues`: same decimals, leading 0 dropped only if needed, never a non-zero as 0, none at all if they can't fit the slot); zero bars get none. `showValues: false` hides, `true` forces. Eval rows 10, 29. Shows on 79 of 103 playgrounds with bars.
  - `structures.seriesLegend` + `components.legendSvg`: 2+ named series (`label`) in different colours get a legend in the plot corner with the fewest marks under it (names already written as text marks are left out). Eval rows 9, 12, 28 (Haiku had named the series; only the tooltip showed it). Drawn on 21 of 182.
  - `validator.cjs` legend message extended to 2+ unnamed bar series (not bars with `labels`) or dot sets in different colours; a chart with a drawn legend counts as named. 10 of 182 get it (eval rows 6, 13, 19). **Rejected:** one dot set coloured per point (classes, eval row 3): flagged 4 of 14 hand-written examples, k-means clusters have no names, too noisy.
  - Prompt (`PLAYGROUND_SYSTEM` mark opts): `label` now says it makes a legend; `showValues` for bars.
- **Nov 2 fixes, part 3** (items #5 and #9):
  - The **y-axis name is drawn above the plot** (`chartFrame` adds `Y_NAME_ROOM` = 10 px to the top margin when there is one; drawn at `M.t - 8` from the y axis). Inside the top-left corner it sat on curves and text marks (eval rows 17, 21, 25). So the heatmap "y-axis name on its cells" message and `_pg_layout_autofix`'s move-it-into-the-title fix are gone, and top edge labels and legends no longer step around it.
  - `structures.axisNames`: an axis name a text mark already writes word for word isn't drawn (eval row 1: 'L(w)' twice; 7 charts of 182). The text mark stays. Repeated text marks are left alone (the 5 found were real repeated values/tokens).
- **Nov 2 fixes, part 4** (items #1, #2, #3; replayed on the same 182):
  - `structures.zoomRange` (used by `chartFrame`, so page and checker agree): **ranges follow the data in view**. A chart with a heatmap: each fixed axis shrinks to what is drawn (eval rows 13, 17). Otherwise a y range **not starting at 0** zooms in by halves (1/4 .. 1/64, windows on an eighth-step grid) when the data fits a quarter of it (eval row 14). Data = lines of 3+ points, areas/bars from 0, dots, rules, rects, arrows, heatmaps (not 2-point guide lines, not text). Never with `zoom: false`, draggable marks / onDrag, diagrams, or flat data. Ranges from 0 are left alone: in the first replay 15 of 45 zoomed charts were sizes growing with a slider (memory, cost, counts), where the fixed scale is the lesson. First view: 25 of 393 charts zoom. Prompt mentions `zoom`.
  - `components.cjs`: an arrow ending on a dot stops at its edge (row 7); a line lying exactly on another (20+ px, every vertex within 2 px) is drawn wide and faint underneath (row 26; 5 charts, e.g. guidance at w = 0); a strip of dots (no yLabel, no line/area/bars/rect/heatmap/arrow, 4+ dots at 1-3 heights, each used twice) has no y numbers or grid (rows 15, 23). `structures.grid`: the agent moves to the corner of a cell with a policy arrow (row 8).
  - `structures.linkGeom`: a link label that would sit on a shape moves above the two shapes (or below) when that spot is free (row 14). The validator's link-label message uses the same spot, so it now fires only when neither is free.
- **Nov 2 fixes, part 5** (items #4-#7):
  - `components.cjs` bars: a bar of 0 (or under 2 px) is drawn 2 px tall on its side of the baseline (eval row 28: the "Q" series at 0 looked missing).
  - heatmap `cellLabels` (2D names): drawn bold above each cell's value (beside it when the cell is under 34 px tall), cut to the cell width; `sandbox.cjs` checks it is a 2D array; prompt heatmap opts mention it (eval row 3: TP/FN/FP/TN; rows/columns were already named, so no "unnamed matrix" message was built).
  - `structures.equalAspect`: equal x/y scales (the axis with spare room gets more range, centred) when `aspect: 'equal'`, or by default for the same fixed range on both axes around 0 with plotted marks only (no bars/heatmap/grid/diagram); `aspect: 'free'` turns it off; such charts don't zoom. Lines drawn to the edge of the spec range are stretched to the widened edge (axis lines). Eval row 15 (PCA directions looked skewed). 36 of 393 charts.
  - `components.cjs` readout: a label ending in (B / bytes / KB / MB / GB / TB) with a value of 10,000+ moves up units (1024 each) while 1024+, and the label's unit follows (eval row 30: 20,480 KB -> 20 MB).
- **Coverage list (Nov 2, from the rubric eval: 48% of lost points were parts of the section left out).** `PLAYGROUND_SYSTEM` Process step 7 asks for `plan.covers`: every setting/mode, intermediate number, worked example, comparison, extreme case, tracked result and key point the section describes, each with the component ids that deliver it (`{need, kind: control|number|view|mark, by}`). The old "focused set ... add a view only if" line was replaced by "deliver every item in covers, and nothing the section doesn't ask for"; components 2-16, sliders "usually 1-5". `validator.cjs` `coverageProblems` (ours, keep when re-copying) returns soft `coverage` messages for items listed but not built (unknown id, no id, wrong kind of component); `facts.covers` carries the list. It can't see what Haiku left out of the list itself. **One soft repair:** `_pg_fix_layout` sends coverage + layout problems in one call (`SOFT_LEAD` when coverage is in it, else `LAYOUT_LEAD`), kept only if every check passes and there are fewer soft problems. "plan.covers is missing" alone never triggers a repair (`COVERS_MISSING`; older saved playgrounds have no list). Stats: `coverage_seen`, `coverage_fixed`, `coverage_left`. `plan_text` stores `covers` on the block.
- **Screenshot check (`_pg_look`, `PG_LOOK`, **off** unless `PG_LOOK=1`; switched off Oct 31: +37% cost, only 2 of 13 repairs kept):** runs on the playground about to be accepted. `scripts/snap-widget.mjs` loads the playground runtime (+ `'unsafe-eval'`) for `XW.playground` html; `look_review` (Code Lab 7.0's judge, `CODE_LAB_LOOK_SYSTEM`) gets `alreadyChecked` = `PG_LOOK_CHECKED` so it skips what the layout check measured. Problems get one repair (`PG_LOOK_LEAD`), kept only if it passes every check, has no more layout problems, keeps the same control labels (Jev's verdict still holds) and its screenshots show fewer problems. Fails open. Not run on follow-up edits yet.
- Repair order: mechanical errors by code first (`_pg_autofix`: draggable point or bar outside chart range, control that changes nothing), the rest by Haiku (`MAX_REPAIRS`); then layout (code, then Haiku, above). Follow-up edits (`codelab_edit.py`) go through the same `_pg_until_clean`.
- The validator's facts include labels inside graph/sequence/tree/matrix marks, so Jev sees a diagram's terms.
- Jev review uses `PG_REVIEW_QUESTIONS` and rejects only below `PG_REVIEW_LOW` (0.2): one fix on a clear no, which must replace an off-topic control rather than rename it; no backup. Buttons that only run it (Play/Step/Resample) are "runs it", not settings.
- Runtime lives in `shared/playground/` (`.cjs`, copied from the experiment). Stored as an ordinary `widget` block: `<div id="pg"></div><script>XW.playground(spec)</script>`. `widget.ts` loads the runtime only for those blocks (`playground-src.ts`), with `'unsafe-eval'` in that frame's CSP.
- Diagram marks: `node/box/circle/diamond` + `link(fromId,toId)` for free-form figures; `graph`/`mlpGraph` for layered layouts (`structures.cjs`, checked in `sandbox.cjs`).
- Prompts `PLAYGROUND_SYSTEM` / `PLAYGROUND_REPAIR`: the helper list must match `shared/playground/helpers.cjs` (`tests/playground.test.ts` checks it).
- Code: `codelab.py` (`_design_playground`, `CodeLabSettings.for_effort(playground=True)`). Follow-up edits: `PLAYGROUND_EDIT` reads the spec back out of the block.
